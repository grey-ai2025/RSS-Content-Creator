### 8. DC Fawcett — AI agent contradicted itself three times in one week
**Post link:** https://www.linkedin.com/posts/dcfawcett_your-ai-agent-contradicted-itself-three-times-activity-7446887356940423169-l9uG
**Post snippet:** "Your AI agent contradicted itself three times in one week. Monday: recommended Strategy A. Tuesday: recommended Strategy B. Thursday: back to a version of A. Nobody noticed until Friday."

**Comment:**
Contradiction without memory is one of the least-discussed failure modes in agentic systems. The agent isn't malfunctioning — it's giving a reasonable answer each time with no context about what it said before. The problem is that the human treating it like a coworker expects continuity that was never built in. Calling that a "hallucination" is the wrong diagnosis.

### 9. Mandi Holmes — RSA 2026: Agents Everywhere, Governed by Nobody
**Post link:** https://www.linkedin.com/posts/mandieholmes_rsa-2026-notes-from-the-civilian-side-this-activity-7443384820858023936-Q2Pw
**Post snippet:** "'Agents Everywhere, Governed by Nobody' was the phrase that kept coming up. The identity/IAM mismatch is the real gap — existing frameworks were built for human users and static software. Neither maps cleanly onto agents that spawn sub-agents, hold credentials, and act at machine speed."

**Comment:**
IAM frameworks assume a human is on the other end of the permission request — someone with a job title, a manager, and an off-boarding date. An agent that spawns sub-agents, inherits credentials, and runs continuously breaks every assumption the framework was designed around. RSA keeps surfacing the gap. The playbook for closing it mostly does not exist yet.

### 10. Oliver Patel — AI governance fails because governance can't match the speed of capability

**Comment:**
Policy written for last quarter's model is already obsolete. That's not a drafting problem — it's a structural one. Governance built around periodic review cycles cannot track a technology that ships meaningful capability changes every few weeks. The answer is probably principles-based rules rather than specification-based ones, but most compliance teams are not set up to operate that way.

**Comment:**
Runtime divergence is the problem that makes benchmarks misleading. A model that scores well on structured evaluations can still make unexpected decisions once it has real tool access, live data, and no human reviewing the intermediate steps. ### 13. TrueHorizon AI — Silent AI agent failure modes nobody talks about: cost amplification, data drift
**Post link:** https://www.linkedin.com/posts/truehorizon-ai_3-failure-modes-that-kill-ai-agents-in-enterprise-activity-7452464905288458240-2_YY
**Post snippet:** "AI agents in production have two failure modes nobody talks about. Not hallucination. Not prompt quality. Cost amplification and data drift — the agent that quietly runs twice as many API calls as scoped, and the one whose behavior shifts as the data it's pulling from changes."

**Comment:**
Cost amplification is the sleeper risk in agentic deployments. A hallucination is visible. An agent that runs 30% more API calls than scoped, every day, for three months, shows up as a budget line item with no obvious root cause. Data drift is worse — the behavior changes without any code change, and the team that built the agent has usually moved on by the time someone notices the outputs look different.
